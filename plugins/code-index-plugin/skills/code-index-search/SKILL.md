# Code Index Search

组合静态代码索引与 `gopls` 的原生 MCP 工具理解代码。健康 `gopls` 返回的符号、引用、包 API、文件依赖和诊断属于高置信语义事实；静态索引负责快速发现候选，源码负责解释业务规则与控制流。

## 能力边界

插件注册两个相互独立的 MCP 服务：

- `code-index`：`get_code_index_status`、`build_code_index`、`refresh_code_index`、`search_code_index`。
- `gopls`：`go_workspace`、`go_search`、`go_file_context`、`go_package_api`、`go_symbol_references`、`go_diagnostics`、`go_vulncheck`、`go_rename_symbol`。

`gopls` 通过原生 `gopls mcp` 接入，不存在 `get_lsp_status` 或 `lsp_*` 工具。只有当前会话真实提供 `go_*` 工具时才能采用其结果；工具缺失、启动失败或工作区识别失败时，直接使用静态索引和源码回退，不要自行安装或启动语言服务器。

## 信源优先级

1. Go 符号、引用、包 API、跨文件依赖和诊断：优先采用健康 `gopls` 的成功结果。
2. 业务规则、控制流、动态注册和运行语义：读取相关源码并结合文本搜索解释。
3. 候选文件、模块、标识符和非 Go 内容发现：使用静态代码索引。
4. `gopls` 或索引不可用、无结果时：使用文本搜索和最小源码读取回退。

不要用文本搜索机械重复证明每个 `gopls` 结果。只有语义结果与当前工作区明显冲突时，才检查工作目录、文件版本、符号名称和语言服务状态。

## 查询流程

### 1. 建立 Go 工作区上下文

当请求涉及 Go 代码并且 `go_workspace` 可用时，尽早调用它确认模块、工作区和根目录。遵循 `gopls` MCP 返回的服务指令处理工作区初始化与漏洞检查，不把启动失败误写成符号不存在。

当请求只涉及非 Go 文件，或当前会话没有 `go_*` 工具时，跳过本步骤。

### 2. 发现候选位置

用户已经给出可靠的 Go 文件或符号时，可直接进入语义查询。否则：

1. 调用 `get_code_index_status` 检查静态索引。
2. `ready=false` 时调用 `build_code_index`。
3. 使用简洁标识符、路由、配置键或领域词调用 `search_code_index`。
4. 查找具体函数、handler 或实现时设置 `prefer_deep_hits=true`；必要时用 `path_prefix` 缩小范围。
5. 对 Go 符号同时使用 `go_search` 消除文本同名歧义。`go_search` 是模糊符号搜索，不要把零结果解释为业务逻辑不存在。

### 3. 用 gopls 确认语义

围绕用户问题选择最小充分工具集：

- 查找 Go 符号定义或实现：使用 `go_search`，再读取命中的最小源码范围。
- 理解一个 Go 文件与同包其他文件的关系：首次读取该文件后调用 `go_file_context`，参数必须是绝对路径。
- 查看包的公开类型、函数、方法和签名：使用 `go_package_api`。
- 查找包级符号、字段或方法的引用和影响范围：使用 `go_symbol_references`；动态注册和字符串引用再用文本搜索补充。
- 排查解析、构建、类型或静态分析问题：使用 `go_diagnostics`；有活动文件时传绝对路径列表。
- 安全或依赖变更涉及漏洞风险时：使用 `go_vulncheck`，并遵循服务返回的工作区要求。
- 用户明确要求重命名 Go 符号时：先用 `go_symbol_references` 评估影响，再调用 `go_rename_symbol` 获取编辑；审阅编辑后才应用并验证。

所有传给 `gopls` 的文件路径使用绝对路径。不要无目的调用全部工具，也不要把 `go_search`、静态索引命中和源码解释混成同一种证据。

### 4. 扩大 gopls 对代码修改的影响

查询过程中若同时需要修改 Go 代码：

1. 修改符号定义前，先用 `go_symbol_references` 检查引用范围。
2. 每批 Go 文件修改后，对已编辑文件调用 `go_diagnostics`。
3. 先修复 error 级诊断，再运行受影响包测试；提示级或信息级结果可按任务相关性处理。
4. 新增或升级 Go 依赖后，使用 `go_vulncheck` 检查受影响工作区。

`gopls` 是语义与诊断信源，不替代测试、业务验证或源码审查。

## 可靠回退

以下情况回退到静态索引、文本搜索和源码读取：

- 当前会话没有 `go_*` 工具。
- `gopls` 未安装、版本不支持 `mcp` 子命令或服务启动失败。
- `go_workspace` 无法识别当前项目。
- 目标不是 Go 代码。
- 语义查询没有结果，或结果与当前磁盘源码明显不一致。

回退不是失败。继续回答问题，并简洁说明哪些结论未经 `gopls` 语义确认；不要把服务不可用表述为 `gopls` 否定了某个定义或引用。

## 输出要求

- 先给最相关结论，再列文件路径和精确行号。
- 将成功的 `go_*` 结果标为“gopls 语义确认”，并与“静态索引命中”“源码解释”区分。
- 定义或引用查询只保留关键位置和必要上下文，不倾倒全部结果。
- `gopls` 不可用时只说明可行动的回退原因，不原样输出服务 stderr。
