# DTO

- 只在输入、输出或序列化结构发生变化时修改 DTO。
- Request / Response 结构体命名应直接表达接口意图。
- 字段名、序列化 tag 和接口契约保持一致；新增字段前检查兼容性和零值语义。
- DTO 变化后搜索 controller 参数绑定、service 入参与返回值、响应组装及测试中的引用。
- 项目按模块组织 DTO 时，沿用 `dto/<module>/` 或当前等价布局。

## 默认规则

- 字段名按 tag 语义转为项目惯用的 Go 命名，例如项目使用 `Id` 时保持 `user_id -> UserId`，使用 `ID` 时保持 `user_id -> UserID`。
- ID、时间戳和状态字段的类型以现有同类结构为准；没有项目证据时，ID 和时间戳可优先使用 `int64`。
- 项目同时使用 `json` / `form` tag 时，新增字段保持双 tag 一致；只使用一种 tag 时不要额外添加。
- 保持项目现有校验 tag、可选字段表示法、导出字段注释和响应空数组约定。
- 不把数据库 model 直接作为外部接口 DTO，除非项目已有明确约定。
