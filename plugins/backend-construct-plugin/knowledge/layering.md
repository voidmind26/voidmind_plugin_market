# 分层边界

- 先根据用户目标和真实调用链确定影响层，不默认扩成完整接口链路。
- 只修改命中层；未命中层除必要的编译适配外不做顺手重构。
- `controller` 只负责参数绑定、调用 service 和统一返回。
- `service` 负责业务规则、业务编排、错误处理和业务日志。
- `data` 负责 model、持久化、查询和缓存访问边界。
- `router` 只负责路由注册和中间件接线。
- `task` 只负责后台任务入口、调度与任务级运行约束，业务逻辑优先复用 service。
- DTO、公共接口或持久化结构发生变化时，必须搜索受影响调用方并保持契约一致。
- 只有需求确实是完整接口新增时，才接近 `dto + data + service + controller + router` 的全链路修改。
