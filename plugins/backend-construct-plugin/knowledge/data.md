# Data

- `data` 负责 model、查询、写入、事务和缓存访问边界；service 不直接拼 SQL 或承载复杂 Redis 命令。
- Data 方法返回结果与 `error`，不吞错；业务错误转换和业务日志通常由 service 或更上层处理。
- 修改查询时检查索引使用、N+1、无依据联表、分页边界和软删除条件。
- 修改写入时检查事务边界、幂等性、唯一键、受影响行数和并发语义。
- 修改缓存时检查 key 组织、TTL、序列化兼容性、回源和失效策略。
- 修改 model 时同步检查查询字段、扫描目标、初始化注册、唯一键和缓存对象。
- 未命中 `data` 时，不因“接口通常需要数据库”而新增持久化改动。

## 默认规则

- 沿用项目已有 `data/mysql/`、`data/cache/`、Repository 或等价目录，不迁移布局。
- 复用项目现有 query builder、ORM 基类、事务辅助函数和 Redis key 常量组织。
- Data 层若已有统一日志或错误包装约定则保持一致；否则避免重复记录同一个错误。
